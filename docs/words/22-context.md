# 上下文窗口

## 一句话

上下文窗口是模型的工作台，不是它的记忆。台面一收，它就忘了。

## 饭桌上可以这么说

- **同事局**：「它没有记忆，只有一张桌子。每问一句，桌上的东西都得重摆一遍。」
- **老板局**：「别把它当档案柜。它一次只能摊开有限的材料，摊太多，中间那些就看不见了。」
- **技术局**：「长上下文不免费。每轮对话都要把历史重新喂一遍，账单跟着长度走。」

## 它到底怎么转的

模型一次能处理的 token 有上限，这个上限就是窗口。你贴的文档、之前的对话，全占这个额度，超了就被截断，或者直接报错让你删。

实验里反复出现一个现象：放在中间的材料最容易被忽略，开头和结尾记得更牢。人开会也这样，第一页和最后一页最清楚，中间翻过去就忘了。这不是模型懒，是注意力被摊薄了。

还有一笔账：每轮对话，历史都要重新送进去算一遍。所以长对话不是「它记住了」，是「你把前面的话又念了一遍给它听」。念得越多，越慢，越贵。

## 说到这儿就该停了

- **错**：「窗口越大，记性越好。」——窗口是台面大小，不是记性。塞得进去不等于看得见；而且窗口越大，单次成本越高。
- **错**：「它记得我们上周聊过。」——除非产品把上次的内容重新贴进这次的窗口，否则它什么都不记得。
- **错**：「把整本书塞进去就行。」——可行，但贵且不稳。真正的问题不是塞不塞得下，是它能不能翻到该用的那几页。
- **追问「那想让它记住怎么办？」**——「把要紧的重写一遍放回窗口，或者让它去外面查。前者叫摘要，后者叫检索。」

## 这个词是怎么被用坏的

「支持超长上下文」写在产品页上，读起来像「记性超好」。它说的其实是「一次能摊开多少纸」。纸多不等于读得懂，更不等于记得住。

这个词被用坏的地方，是把容量偷换成了能力。容量可以买，能力不行。
