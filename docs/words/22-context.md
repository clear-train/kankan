# 上下文窗口

## 一句话

窗口大不等于记性好。它只是桌子大，桌上压着的那叠照样看不见。

## 饭桌上可以这么说

- **同事局**：「它不记得上一轮。是你每一轮都把上一轮重新念给它听。所谓记忆，是你在替它记。」
- **老板局**：「窗口大只说明台面大。中间那几页它照样翻不到，账单倒是按长度收。」
- **亲戚局**：「像开长会，桌子就那么大，材料堆到胸口，中间那叠谁都不翻。」

## 它到底怎么转的

它一次能处理的 token 有上限，这个上限就是窗口。你贴的文档、之前的对话，全摊在这张台面上。超了，从开头砍；再超，直接报错让你删。

拍出来是这样的：会议室长桌上从左到右摆一溜 A4 纸。开头几张看得清，最后几张也看得清，中间那叠被前面挡住，只露出个边。实验里反复看到同样的现象——放在中间的材料，最容易被跳过。

还有一笔账：每轮对话，历史都要重新送进去算一遍。所以长对话不是它记住了，是你把前面的话又念了一遍给它听。念得越多，越慢，越贵。长度就是账单。

## 说到这儿就该停了

- **错**：「窗口够大，它就能记住整本书。」——塞得进去和读得出来是两件事。它可能翻到第 3 页和第 900 页，中间那 800 页只贡献了长度。
- **错**：「它记得我们上周聊过。」——除非产品把上次的原文又贴了进来。否则它每次都是第一次见你，而且态度还一样热情。
- **错**：「上下文不要钱。」——按 token 计费的东西，长度就是价格。把整本手册贴进去问一句，等于打车绕城一圈去买瓶水。
- **追问「那怎么让它记住？」**——「把要紧的重写一遍放回台面，或者让它出门去查。前者叫摘要，后者叫检索，都不叫记性。」

## 这个词是怎么被用坏的

「支持超长上下文」是一句好广告，因为「长」听起来像「记性好」。它说的其实是桌子大。桌子大是工程能力，记得住是另一回事，这两件事被一个数字焊在了一起。

参数表上写的是容量，用起来才发现瓶颈在读，不在装。买桌子的人越来越多，量过记性的人很少。发布会讲容量，报价单讲单价，两页纸中间隔着一句「以实际计费为准」。
