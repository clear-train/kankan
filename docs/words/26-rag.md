# RAG（检索增强生成）

## 一句话

先查资料，再开口。RAG 给模型配了一个开卷考试的考场。

## 饭桌上可以这么说

- **同事局**：「它不是变聪明了，是允许它翻书了。翻得对不对，全看前半段那个检索。」
- **老板局**：「私有数据、知识过时、瞎编，它能救一部分。救不救得回来，看找得准不准。」
- **亲戚局**：「像开卷考试。书就在旁边，翻错页照样答错，而且答得特别理直气壮。」

## 它到底怎么转的

先把资料切成小段，每段变成一串数字，存进库里。这串数字叫向量，代表意思：意思相近的段落，数字也相近。

你提问时，问题也变成一串数字，去库里找最接近的几段，把它们原文拼进提示词，再让模型「照着这些材料回答」。

所以它同时解决三件事：有据可依，少瞎编；材料随时能换，不怕过时；能读私有文档，不用重新训练。难点几乎全在前半段：切得碎不碎，找得准不准。

## 说到这儿就该停了

- **错**：「接了 RAG 就不会幻觉了。」——材料里没有答案，或者检索拿错了段落，它照样编，而且更有底气，因为它「有引用」。
- **错**：「RAG 是让模型学会新知识。」——它不改模型，只是每次把材料临时塞进上下文。关了检索，它还是原来那个它。
- **错**：「向量检索懂语义，所以一定准。」——相似不等于相关。同一个问题换个问法、同一个词指两件事，都是常翻车的地方。
- **追问「那 RAG 最难的是什么？」**——「不是生成，是找。找对了，生成顺水推舟；找错了，生成雪上加霜。」

## 这个词是怎么被用坏的

RAG 在中文里常被说成「知识库问答」，于是它成了一个产品名：接上你们的文档，就有个懂你们业务的 AI。

真实情况是，它把一半的难题从「模型会不会说」挪到了「资料找不找得到」。后者是搜索问题，不是模型问题。这一点，卖方案的人通常不提。
