# 多智能体（Multi-Agent）

## 一句话

多个模型一起干活，多半不是它们商量得好，是分工把它们各自的毛病挡住了。

## 饭桌上可以这么说

- **同事局**：「不是开会，是各交一份作业，再有个判卷的。」
- **老板局**：「它的好处不在更聪明，在可回滚——哪一步错了只重跑那一步。」
- **亲戚局**：「像装修队，水电木工各管一段，谁也不指挥谁。」

## 它到底怎么转的

工程上常见三种搭法。流水线：把任务切成几段，每段一个角色，上一段的输出是下一段的输入。主管加工人：一个负责拆活和验收，其余负责干。辩论与投票：同一个问题让几个模型各答一遍，再由一个裁判挑，或者按票数定。

外面说的「开会」，实际发生的是共享上下文：要么大家读写同一段记录，要么互相发消息，消息被追加进上下文。没有谈判，因为模型没有偏好，也不会因为上一轮吃了亏而改主意。所谓「陶片放逐」，对应的是投票与淘汰：候选多答几个，选一个，剩下的丢掉。名字很古典，机制很朴素，就是采样加筛选。

这套东西有用，有个前提：答案可验证。跑测试、对数、比对格式，裁判能直接看到对错，多花几份算力确实能换来更稳的结果。反过来，答案没法验证时，裁判也只能凭感觉，投票只是把同一个偏见平均了 n 次，而且看起来更权威。

代价是明码的：token 和延迟大致按参与者数量线性上涨；失败还会级联，上游说得漂亮但不对，下游会非常认真地执行到底。

## 说到这儿就该停了

- **错**：「多智能体等于更强的智能。」——多数增益来自分工与重试，不来自讨论。单模型配一个好 harness，常常更便宜也更稳。
- **错**：「它们在开会。」——它们在轮流写同一段上下文。会开得越久，上下文越脏，越像一场没人记会议纪要的会。
- **错**：「投票能纠错。」——答案可验证时能；不可验证时不能，只会让错误变得有仪式感。
- **追问「什么时候该上多智能体？」**——「两件事同时成立：任务能切成互不依赖的段，每段有可检查的交付物。少一条，你得到的就是一群互相点赞的实习生。」

## 这个词是怎么被用坏的

演示里三个小人来回讨论，看着像开会，卖的是热闹。真进生产，最先暴露的往往是延迟和账单，而不是能力。判断标准很土：把「讨论」那一层删掉，只留分工和检查，成绩掉多少。掉得少，说明讨论是表演；掉得多，才轮到它叫设计。
