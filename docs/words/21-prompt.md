# 提示词工程

## 一句话

提示词不是咒语，是一份写给不会追问你的实习生看的需求文档。

## 饭桌上可以这么说

- **同事局**：「魔法词不玄。它只是把你开头那几个字换了个方向，剩下的它顺着写。」
- **老板局**：「别研究怎么咒它，研究怎么把需求写清楚。这一件事，能省一半返工。」
- **亲戚局**：「跟派活给新来的实习生一样：给个样板，比说十句‘你懂的’管用。」

## 它到底怎么转的

你在教一个从不追问的人写请假条。你说「写个请假条」，他交上来八百字抒情散文——因为他读过的请假条里，真有人这么写。你改成「三行，第一行事由，第二行日期」，他就写对了。

四件套就是把这句交代补全：角色（谁在写）、任务（写什么）、约束（几行、什么格式、不许出现什么）、示例（贴一份合格的）。前三条划范围，第四条给模板。模板比形容词有用，因为它是具体的。

它在续写，你写的是开头。开头提到哪类文本，它就往哪个语域里续。所谓咒语，多半只是碰巧拨动了这个开头分布，换个模型就没了。你没改变它的能力，你改变了它站在哪个书架前。

## 说到这儿就该停了

- **错**：「提示词有魔法词，加一句就翻倍。」——那句话在一个模型上碰巧管用，因为它在语料里常出现在好答案前面。你抄的是巧合，不是方法。
- **错**：「提示词能突破模型的上限。」——它只能把已有的能力问出来。问不出来，是它真没有，不是你话说得不够狠。
- **错**：「提示词写好了，换什么模型都一样。」——同一句话，在两个模型上是两份不同的开头。换模型要重调，这是体力活，不是玄学。
- **追问「提示词工程师算技术岗吗？」**——「算半个。核心技能是把需求写清楚。这技能一直很贵，只是以前收需求的人会追问你。」

## 这个词是怎么被用坏的

「提示词工程师」这个岗位名，寿命大概和「网页设计师」差不多：先是个新物种，再是标配，最后没人再提。招聘启事上写「熟悉各类咒语」的那几年，稀缺的其实不是咒语，是能把业务说清楚的人。咒语好学，业务难学，所以那批启事后来大多改成了「懂业务优先」。

词退潮了，活还在，只是改回了旧名字：写需求。写不清楚的人，换哪个模型都写不清楚。
