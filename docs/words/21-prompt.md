# 提示词工程

## 一句话

提示词不是咒语，是给模型铺一个更好的开头。

## 饭桌上可以这么说

- **同事局**：「提示词不是玄学，是把话说清楚。谁需求写得清楚，谁就占便宜。」
- **老板局**：「别指望咒语。角色、任务、约束、例子，四样给全，返工能少一半。」
- **亲戚局**：「跟教新来的实习生一样，你说得越具体，他做得越像样。」

## 它到底怎么转的

模型一直在续写。你写的提示词，就是它要接着往下写的那段开头。开头写「请写一首诗」，它就往诗的方向续；开头写「你是个苛刻的编辑，请挑错」，它就把语料里「编辑挑错」那类文本调出来续。

所谓四件套，就是把这个开头铺得更准：角色（谁在说话）、任务（要什么）、约束（多长、什么格式、不许做什么）、示例（长什么样算合格）。前三样缩小范围，第四样直接给它一个照着写的模板。

它有效，不是因为它懂你，是因为语料里「好开头」后面的文本，平均质量确实更高。你挪动的不是它的智力，是它接话的方向。

## 说到这儿就该停了

- **错**：「提示词有魔法词，加一句‘深呼吸’，效果翻倍。」——个别技巧在个别模型上碰巧有效，多半是改变了开头分布，换个模型就失灵。清楚比玄妙可靠。
- **错**：「提示词写好了，用什么模型都一样。」——提示词是跟具体模型、具体版本磨出来的，换模型要重调。
- **错**：「提示词能突破模型的能力上限。」——它只能把已有的能力问出来，问不出来就是没有。
- **追问「那提示词工程师算技术吗？」**——「算半个。它更像写清楚需求的能力，只是这次收需求的人不会追问你。」

## 这个词是怎么被用坏的

「提示词工程师」一度被说成新工种，传说薪水很高，招聘要求是熟悉各种「咒语」。后来大家发现，这份工作的大部分内容是把需求写清楚——这件事一直有人在做，只是以前不叫这个名字。

词没有坏，是它被包装成了一个入口：好像学会几句咒语，就能绕过理解业务这件事。
