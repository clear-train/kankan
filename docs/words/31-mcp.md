# MCP 与工具调用

## 一句话

模型不会用工具，它只会说「我想调第三个函数」——真正动手的是外面那个程序。

## 饭桌上可以这么说

- **同事局**：「工具调用是模型吐一段结构化请求：调哪个函数、参数是什么。执行在宿主程序，它碰不到。」
- **老板局**：「MCP 干的是接口标准化。以前每接一个工具写一套胶水，现在按一个协议来，像 USB-C。」
- **亲戚局**：「像给它配了个翻译，让它能跟外面的系统说话。它自己还是不会用那些系统。」

## 它到底怎么转的

你在请求里附一份工具清单：名字、用途、参数格式。模型读完清单，输出一段符合格式的调用请求，然后停下。**注意它停了**——跑代码的是外面那层程序。

程序执行完，把结果作为一条新消息塞回去，模型接着往下写。所以「用工具」说到底还是生成，只是生成出来的东西被当成了指令。

MCP 是把「工具怎么描述、怎么发现、怎么调用」定成一套通用协议。以前 M 个模型接 N 个工具，要写 M 乘 N 套适配；现在两边各实现一次协议，变成 M 加 N。USB-C 的比喻就是从这儿来的。

## 说到这儿就该停了

- **错**：「接上工具，模型就变聪明了。」——它多了手，脑子没换。工具让它能查、能算，不提高它对世界的理解。
- **错**：「MCP 是模型的一部分。」——它是协议，是外面的连接层。换模型、换工具，协议还在那儿。
- **追问「那工具接得越多越好？」** ——「不一定。工具越多，选错的概率越大，能碰到的危险面也越大。权限该收着给。」

## 这个词是怎么被用坏的

MCP 火了之后，所有「支持插件」都改叫「支持 MCP」。协议解决的是接线问题，不解决信任问题。工具清单是给模型看的，那它就是攻击面：一段写歪的描述，就能让它去调不该调的东西。
