# MCP 与工具调用

## 一句话

它统一的是插头，不是电器。插座变多了，不代表你家的电器变好了。

## 饭桌上可以这么说

- **同事局**：「模型不会用工具。它只输出一句『我要调这个函数』，然后停下，等外面去跑。」
- **老板局**：「以前接一个工具写一套胶水，现在按一个协议来。像 USB-C，统的是插头。」
- **亲戚局**：「像给它配了个翻译，让它能跟外面的系统说话。它自己还是不会用那些系统。」

## 它到底怎么转的

你在请求里附一份工具清单：名字、用途、参数长什么样。模型读完，输出一段结构化的调用请求，然后停下。跑代码的是外面那层程序，它从没碰过你的服务器。

结果被塞回上下文，它接着往下写。所以「用工具」说到底还是生成，只是生成的东西被当成了指令。这也解释了它为什么会调错：它在猜，哪个函数最像此刻该用的那个。

MCP 把「工具怎么描述、怎么发现、怎么调用」定成一套协议。以前 M 个模型接 N 个工具，要写 M 乘 N 套适配；现在两边各实现一次，变成 M 加 N。**它省的是接线，不是判断。**

## 说到这儿就该停了

- **错**：「接上工具，模型就变聪明了。」——它多了手，脑子没换。能查、能算，不等于理解，它只是把外部结果读进上下文。
- **错**：「MCP 是模型的一部分。」——它是外面的连接层，一份协议。换模型、换工具，协议还在。
- **错**：「工具越多，能力越强。」——工具越多，选错的概率越大，能碰到的危险面也越大。权限清单越长，出事的方式越多。
- **追问「那它安全吗？」**——「安全不取决于协议，取决于你给了它什么权限：能读什么、能写什么、能不能删。这三件事比协议重要得多。」

## 这个词是怎么被用坏的

MCP 火了之后，所有「支持插件」都改叫「支持 MCP」，就像所有带插头的都叫 USB-C。

协议解决接线，不解决信任。工具清单是写给模型看的，那它就是攻击面：一段写歪的描述，就能让它去调不该调的东西。标准化省下的工时没有自动变成安全，只是让不安全的东西接得更快。省下来的那点时间，多半花在了给每个新工具配权限上。
