# 向量数据库

## 一句话

它只答应你够快，从不答应你找对；找对是别人的活，账单却记在它头上。

## 饭桌上可以这么说

- **同事局**：「它按意思找，不按字找。你把『退款』写成『退钱』，它照样捞得回来。」
- **老板局**：「数据没到量级，别买。为了两百人开会租体育馆，钱花了，人还得站着。」
- **亲戚局**：「像让一个只记得大概的人帮你找书。找得到，但别问他页码。」

## 它到底怎么转的

文字没有位置，只有字面。传统索引按字建目录，所以「退款」和「退钱」在它眼里是两个毫不相干的词。向量库换了个办法：先把每段话压成一串数字，意思近的，数字靠得近。

查询时，它要算你的问题和每一条的距离。一百万条，就是一百万次减法。于是它用近似最近邻，简称 ANN：先把数据分成许多堆，查询时只翻附近那几堆。**它用「可能漏掉」，换了一个数量级。**

所以数据量小的时候，它没有优势。几百条数据，全量算一遍更准，也更快。它的价值只随数据量增长，不随你多需要它增长。

## 说到这儿就该停了

- **错**：「向量数据库懂语义。」——它只算距离。语义是上游那个向量模型给的，它不认识字，只认识数组。
- **错**：「上了向量库，问答就准了。」——它只负责把候选捞回来。捞错了，后面那个模型会用很通顺的话，把错答案讲完。
- **错**：「相似就是相关。」——两段话挨得很近，可能只是在说同一件事的反面。「热」和「冷」在向量空间里常常是邻居。
- **追问「那什么时候才该上？」**——「数据多到全量比一遍会超时的时候。在那之前，它解决的是一个你还没有的问题。」

## 这个词是怎么被用坏的

它成了 RAG 的同义词，RAG 成了「让 AI 读懂我们文档」的同义词。于是一个只管检索的零件，被写进了发布会的价值主张。

招聘要求写「熟悉向量数据库」，入职以后，一天里大半时间在调切块大小和重排权重，还要解释它为什么没同事说的那么灵。产品页写毫秒级，小字写数据规模。真正吃时间的那部分，清洗、切分、重排，没有截图可放。
