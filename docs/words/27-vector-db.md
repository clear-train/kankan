# 向量数据库

## 一句话

传统数据库找「相等」，它找「像」——这是两种完全不同的问法。

## 饭桌上可以这么说

- **同事局**：「它把‘相似’做成了索引。你给它一句话，它还你十条最像的，不是唯一正确的那条。」
- **老板局**：「资料只有几千条的时候别上它。放进表格里全算一遍，比它快，也少一个人维护。」
- **亲戚局**：「像查字典和找人问路。字典要你拼对字，问路说个大概也能到。」

## 它到底怎么转的

文字和图片会先被一个模型压成一串数字，这串数字叫向量。意思相近的东西，向量在空间里离得近，所以「猫」和一张猫的照片会被摆到相邻的位置。

传统数据库的索引擅长回答「等于几」，向量库要回答的是「离谁最近」。逐条算距离太慢，于是它用近似最近邻，简称 ANN：先把数据粗粗分堆，查询时只翻附近那几堆。

代价是可能漏掉真正最近的那条。**它拿一点准确率，换了一个数量级的速度。** 所以数据量小的时候它没有意义，几千条直接算就行；它值钱是在百万条以上。

## 说到这儿就该停了

- **错**：「向量数据库懂语义。」——它不算语义，只算距离。语义是生成向量那一步的模型给的，它只负责存和查。
- **错**：「上了向量库，问答就准了。」——它只把候选段落捞回来。答得对不对，看后面那个写答案的模型。
- **追问「近似会不会漏掉正确答案？」** ——「会。它不保证全对，只保证够快。要全对就得全量算一遍，那就不叫近似了。」

## 这个词是怎么被用坏的

它现在是 RAG 的同义词，而 RAG 是「让 AI 读懂我们公司文档」的同义词。产品页写「毫秒级语义检索」，小字写数据规模。真正决定效果的切块、重排、清洗，没人提，因为那些不好卖。
