# 模型路由

## 一句话

路由是拿一个便宜的问题，决定要不要去问那个贵的。

## 饭桌上可以这么说

- **同事局**：「先让便宜的问一句『这活要不要请老师傅』，要，再请；不要，前台自己办了。」
- **老板局**：「账单的大头不是贵模型，是拿贵模型去干便宜活。路由就是那道闸。」
- **亲戚局**：「像医院分诊台。护士先看一眼，感冒去普通门诊，别都往专家号里挤。」

## 它到底怎么转的

路由本身是个很小的判断：这句话要不要检索、要不要上大模型、要不要转人工。便宜模型或小分类器做完，吐一个标签，标签决定后面走哪条路。Jev 这类决策模型干的就是这个判断层（[Jev 与决策模型](/words/39-jev)）。

省下来的是期望值，不是单价。便宜路径答对的比例乘便宜价格，加上错判的比例乘返工成本，才是真账。路由错了，省下的钱在返工里还回去，有时候还带利息：用户问了三遍才发现答错。

路由表还会腐烂。模型升级、价格变动、业务换了问法，规则还停在配它的那天。没人给它写测试，它就慢慢把所有问题都判成简单。失灵是安静的，账单上只显示最近省了不少。

## 说到这儿就该停了

- **错**：「路由就是按价格选模型。」——比价只看贵不贵，路由看这活的难度和风险，两者经常相反。
- **错**：「路由错了，最多慢一点。」——错在「该上贵的没上」，用户拿到一个自信但错的答案，返工比一开始就上贵模型更贵。
- **错**：「路由表配一次就完了。」——模型在换、问法在变，不维护就退化成随机。
- **追问「那怎么知道路由准不准？」**——「留一小部分流量不走路由，直接给贵模型，定期比对。这笔钱是保险费，不交就得在客诉里交。」

## 这个词是怎么被用坏的

「模型路由」听着像交通调度，落地常是一条 if-else 加一个关键词表。会上讲智能路由，讲的是省了多少；没人讲那批被分错、又没人发现的请求。判断标准很土：路由错了，你有没有办法知道。知道不了，那就不叫路由，叫抽签。
