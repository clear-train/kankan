# DeepSeek 把整个 App 拆成接口卖了

## 发生了什么

2026 年 11 月 13 日，DeepSeek 发布「全家桶应用 API」：原来只有模型接口，现在把 App 里的那套功能一起开放——联网搜索、思考模式下的多步搜索、文件输入（PDF、Office、图片）、自动读链接，还有模型安全校验；语音相关的 OCR、ASR、TTS 也给独立接口（[DeepSeek API 文档，2026-11-13](https://api-docs.deepseek.com/zh-cn/news/news261113/)）。

关键在实现方式：这些不是让你自己拼的工具，是打开参数就生效——工具调用和上下文拼接由服务端完成，目前由 V4.1-Flash（`deepseek-flash`）在三种接口下支持。官方还开源了一份前端 Demo，说能「1:1 复刻出完整的 DeepSeek App」。

计费也变了：除 Token 费，工具调用单独收费。官方公告里的价格表是一张图片，没给文字版数字，这里就不抄了。

## 大家怎么说

开发者的第一反应是省事：以前接一个「能查资料、能读文件、能听语音」的应用，要自己拼搜索、解析、语音三套服务，还要处理调用衔接；现在一个参数。

第二反应是算账：Token 便宜、工具贵，是两种成本。搜索一次、解析一个 PDF、转写一段音频，都按次计。

第三种反应更冷静：官方公告里那句「如您对外提供应用服务，请务必开启该参数，并承担内容安全审核、大模型登记、AI 标识等义务」——能力开放的同时，责任也一起交出来了。

## 拆开看

这件事真正的意思不是「模型更强了」，是**把 App 里的脏活变成了计费项**。

过去两年，模型之外的活——检索、抓网页、切文件、语音进出、内容风控——一直是各家自己写、自己踩坑的部分。它属于 harness 那一层：翻译工具清单、真发调用、把结果塞回去再问（这条线可以看[一次调用走了几步](/appendix/how-it-runs)）。

现在厂商把它商品化，等于承认两件事。一是智能体的钱不全在 Token 上，在「工具调用次数」上；二是这层脏活标准化之后，做应用的门槛会掉一大截——一个两个人团队也能做出体验接近大厂的产品。

代价在另一头：工具进了黑箱，你就不再知道搜索结果是怎么排序的、解析丢没丢表格、风控拒了什么。能 1:1 复刻 App，也意味着能 1:1 继承它的取舍。

## 一年后再看

留三条可验证的判断，到 2027 年年中回来对：

一，主流厂商都会把「搜索、解析、语音、风控」做成默认计费项，而不是让开发者自己拼。已经这么做的会被当成标配，不做的会被当成半成品。

二，模型单价继续降，工具单价不降。因为工具的成本是别人的：搜索要索引，抓网页要带宽，OCR 要算力。

三，应用层会出现一批「只做壳」的产品——界面自己写，能力全调，毛利薄但上线快。它们的护城河只有一处：谁更懂某个具体场景的授权与责任。

## 这一篇的保质期

写于 2026 年 11 月 15 日。预计有效到 2027 年年中。

失效标志有三个：DeepSeek 改成统一按 Token 计价；主要竞品仍然只卖模型、不卖工具；出现因为工具调用费而大规模回迁自建的案例。
