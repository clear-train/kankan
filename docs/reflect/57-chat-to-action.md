# 聊着天，事情就做完了

## 一个场景

出租车后座，老陈对着手机说：「把这一周的会议纪要整理成周报，顺便订明天十点去上海的票。」说完把手机扣在腿上，看窗外。两分钟后手机震了两下：一份周报，三个要点，语气像他自己写的；一张车票订单，明早十点，虹桥。他给同事发消息：「以后这活不用自己干了。」晚上在酒店，日历弹出提醒：下周二，十点，虹桥。他把订单翻出来，日期那一栏写着下周二。改签要多付钱，他付了。

## 它是怎么转的

过去三十年，软件的门槛是「你得知道按钮在哪」。菜单、表单、审批流，本质都是替人做翻译：把你的意图拆成步骤，让你一步步点下去。现在这一步被拿掉了，你直接说意图，机器自己去找按钮。

界面先消失。流程从原型图搬进了提示词，产品经理能定下的东西变薄了——以前争「主按钮放哪」，现在争「这句话怎么说才不产生歧义」。产品从「画出来」变成「写清楚」。

接着是权限。能聊天就能操作，等于把权限系统挪到了对话层。翻车的典型不是它不会做，是它太听话。你说「都删了吧」，它真的都删了。

最后是过程。点按钮的时候，你知道自己点了几步；聊天的时候，你只看到结果，中间那十步在后台跑。「它做对了」和「它做了什么」从此是两件事，审计成本就是这么涨上去的。

[《边界》](./56-boundary.md)那一篇讲的是能力边界和权限边界不是一回事。这一篇讲的是另一个方向：当操作变成请求，边界就从系统挪到了人的语气里。

## 饭桌上可以这么说

- **同事局**：「以前是找按钮，现在是把话说清楚。」
- **老板局**：「上这套东西之前先问一句：谁按确认键。以后最贵的岗位就是按确认键的那个。」
- **亲戚局**：「它能听懂你，不代表它听懂了后果。」

## 说到这儿就该停了

- **错**：「界面要消失了，App 都得改成聊天框。」——界面没消失，是退到后台去了。聊天框是最贵的一种界面，因为它不告诉你边界在哪。
- **错**：「会说话就能操作，门槛降低了。」——门槛从「学软件」挪到了「说清楚、担后果」，后一样没法外包。
- **错**：「机器把事做完了，人只要验收。」——验收的前提是知道对的样子。过程不可见的时候，你验的是结果，不是路径。
- **被追问「出了事算谁的？」**——「算按确认键那个人的。所以现在最贵的不是会写提示词的，是敢签字的。」

## 最后

那天晚上他把票改签了，多花几十块。周报一个字没改，因为看不出来哪里不对。这才是新问题：不是机器会不会做错，是你还说不说得清它做了什么。下一回，你还敢让它「顺便」吗。
