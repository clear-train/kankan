# 为什么 To B 这么难

## 一个场景

汽配厂的会议室没有窗，投影的风扇一直在响。销售讲了二十分钟 AI 客服能省多少人，采购主任把笔放下，笔滚了半圈，停在桌沿。「能不能接我们那套 2013 年的 ERP。」技术说能，做个接口。主任又问：「半夜出了问题，谁值班。」销售说我们 7×24 小时响应。主任说：「我问的是谁的名字。」销售低头翻了一页 PPT，会议室里有人咳了一声。三个月后，那个 POC 还在跑，主任调走了。新主任翻完材料，说：「这个项目不是我批的。」

## 它是怎么转的

To C 是说服一个人，To B 是说服一张组织图。老板点头只是第一关，用的人、管数据的人、签字的人、财务、法务，每一格都有一票否决权。而且没有谁会因为「买了没出事」被表扬。

企业买的其实不是效率，是责任。采购真正要问的是「出了事谁兜着」。AI 最难给的偏偏就是这个：它输出的是概率，不是承诺。所以合同、验收、驻场、响应时间这些不性感的东西，比模型能力更决定成败。招标文件里最贵的那一栏，通常写着「服务」。

收入结构也不一样。To C 一套产品卖给一千万人，边际成本几乎为零。To B 每来一个客户就要定制一遍，实施、对接、培训，一样都省不掉。这就是为什么 To B 公司长得慢，但也更难死。

最要命的是时间。一个项目从立项到验收，常常比一任负责人的任期还长。人一换，前面积累的信任要重新攒，上一轮答应你的事，没人认账。所以 To B 的核心资产，往往不是产品，是那个人的名字。

## 饭桌上可以这么说

- **同事局**：「To B 卖的不是软件，是半夜三点接电话那个人的名字。」
- **老板局**：「To C 打广告，To B 打样。样打不完，单签不下来，人先走了。」
- **亲戚局**：「跟装修一样。谈的时候都行，住进去才知道漏水，再找人，电话停机了。」

## 说到这儿就该停了

- **错**：「To B 难，是产品不够好。」—— 好产品多得是。卖不动的，多半是「出了事没人接电话」。
- **错**：「搞定老板就行。」—— 老板点头只买到入场券。真正卡你的是每天要用它的人，和那个要签字的人。
- **错**：「AI 能标准化，To B 会变简单。」—— 标准化的是模型，不是每家的流程、历史包袱和人际关系。
- **追问「那 To B 的 AI 是不是没戏？」**——「有戏，但慢。它的节奏不跟模型迭代走，跟预算周期和人事变动走。」

## 最后

那个 POC 后来上线了，用的是另一家供应商。价格贵一点，但他们派了两个人常驻厂里。主任签字那天说了一句话：不是你们的东西好，是你们的人在。这句话做 AI 的人不爱听。它等于承认，这一行最后卖的，还是人。而人是不能按 token 计费的。这句话后来被写进复盘，小标题叫《客户关系的重要性》。
