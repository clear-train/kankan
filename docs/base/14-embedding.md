# 参数与向量：意思可以被算出来

## 一句话

意思在它那里不是解释，是坐标；两个词挨得近，是因为常出现在同一种句子里。

## 饭桌上可以这么说

- **同事局**：「每个词是空间里的一个点。近义词住隔壁，搜索和推荐都靠这个。」
- **老板局**：「参数多不等于懂得多，只等于坐标密。地图再细，也不认识路。」
- **亲戚局**：「像给每个词在地图上标一个点。意思像的，标在隔壁。」

## 它到底怎么转的

模型只认数。所以先把词变成一串数字，叫向量，当成高维空间里的一个坐标。训练时，老在相似上下文里出现的词，坐标被慢慢拉近。拉的过程没有谁在设计，只是统计一路推下来。

经典例子是「国王 − 男人 + 女人 ≈ 女王」。它在早期的词向量模型里最明显：从男人到女人的方向，和从国王到女王的方向差不多。这是语料搭配规律的副产品，不是逻辑推理。今天的大模型，一个词的意思随上下文变，这种静态的几何关系就没那么干净了。

这些数字，加上连接它们的权重，统称参数。高维空间画不出来，任何三维示意图都是压缩后的隐喻，看个意思就行。RAG、推荐、聚类，地基都是这一步：把东西变成向量，再比距离。

## 说到这儿就该停了

- **错**：「『国王 − 男人 + 女人 = 女王』，说明它会类比推理。」——那是一条语料里的方向，不是一次推理。它只在线性词向量上成立，今天的大模型得先问清是哪一层。
- **错**：「向量能算，说明模型理解了意思。」——它算的是共现。方向成立，是因为语料里总这么搭配。
- **错**：「可以把它画成三维空间。」——几百到几千维，人的眼睛没有这个接口。画出来的都是比喻。
- **追问「那向量里到底存了什么？」**——「存的是『这个词常和谁一起出现』。意思是我们从这些共现里读出来的。」

## 多说一句

RAG 的地基是几何，不是逻辑：问题变成点，文档变成点，找最近的几段塞回去。它判的是像不像，不是对不对。所以检索回来的东西，相关性通常不错，正确性另说。地图画得好，不等于路修通了。这句话对向量数据库同样成立：它卖的是地图，不是路。
