# 参数与向量：意思可以被算出来

## 一句话

意思可以变成坐标，坐标挨得近，意思就挨得近。

## 饭桌上可以这么说

- **同事局**：「每个词是一串数字，也就是空间里的一个点。近义词住得近，搜索和推荐都靠这个。」
- **老板局**：「参数就是这堆数字的总和。说模型多大，说的就是它有多少个这样的数。」
- **亲戚局**：「像给每个词在地图上标个位置，意思像的词，标得近。」

## 它到底怎么转的

模型不认识字，只认识数。所以先要把词变成一串数字，这串数字叫向量，可以理解成高维空间里的一个坐标。训练时，总在相似上下文里出现的词，坐标会被慢慢拉近。

经典例子是「国王 − 男人 + 女人 ≈ 女王」。它在早期的词向量模型里最明显，说明某些语义关系在向量里表现为一个方向：从男人到女人，和从国王到女王，方向差不多。它不能说明模型在做逻辑推理，只是语料里搭配规律的副产品。到了今天的大模型，一个词的意思随上下文变，这种静态的几何关系就没那么干净了。

所有这样的数字，加上连接它们的权重，统称参数。高维空间画不出来，任何三维示意图都是压缩后的隐喻，看个意思就行，别当真。RAG、推荐、聚类，地基都是这一步：把东西变成向量，再比距离。

## 说到这儿就该停了

- **错**：「向量能算，说明模型理解了意思。」——它算的是共现规律。方向成立，是因为语料里总这么搭配。
- **错**：「可以把它画成三维空间。」——几百到几千维，人的眼睛没有这个接口。
- **错**：「国王减男人加女人一定等于女王。」——近似成立，不是恒等式。它是个好例子，不是一条定律。
- **追问「那向量里到底存了什么？」**——「存的是『这个词常和谁一起出现』。意思是我们从这些共现里读出来的。」

## 多说一句

RAG 能成立，靠的就是比距离：问题和文档都变成向量，找坐标最近的几段塞给模型。它判断的是「像不像」，不是「对不对」。所以检索回来的东西，相关性通常不错，正确性另说——这一步的地基是几何，不是逻辑。
